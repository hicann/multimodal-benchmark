# v0.15：修复后端产物采集，增加独立模式认证门禁

## 不变的评测边界

这是新的冻结版本 `v0.15-backend-capture-fix-candidates`，不原地更改已经真机执行的 v0.14 资产。全部 1377 个用例内容哈希、输入、参考、容差与 71 标签分母不变，保留原有 68×20 个基础用例；提交侧 Python 内核与 v0.14 逐字节相同。静态覆盖仍为 67/71（94.37%）。

本轮修复采集与报告机制，不通过增删用例、放宽断言或改写标签含义补分。本机合成编译器测试不计为真实 NPU 认证。

## 针对 v0.14 真机缺口的修复

### 1. 从输出前缀找到真实二进制

真机命令的 `-o /tmp/.../kernel` 不一定代表一个同名文件。现在同时支持 `-o path`、`-o=path`，在编译调用前后比较有界目录清单，保存本次新建或修改、属于该输出前缀的文件：精确文件、前缀点后缀文件，以及输出目录中的文件。不限于猜测某个 `.o` 扩展名。

每个输出候选保存完整字节及哈希，并进入 supervisor 原有的产物索引。离线认证逐个读取并校验候选，只有其内容与实际 JIT 返回的 `npubin` 逐字节相等才建立绑定。输入依旧必须逐字节等于该次 `ttadapter`，编译必须成功，工具哈希、同名内核与快照完整性要求均保留。

没有改变的旧输出、符号链接、无关文件或不匹配的候选不能提供本次编译身份。身份匹配后，才允许原有同进程、同运行目录、同 manifest、同输入/二进制特化的证据复用；复用继续单独标记，不冒充新编译。

### 2. 增加厂商过滤选项与文件树采集

继续从当前安装编译器的帮助探测能力，只使用帮助明确列出的选项。若存在厂商 `--bishengir-print-ir-after`，请求 `canonicalize` 后的快照；这个 pass 名在 v0.14 的实际 dump 中已经出现，不猜测未知后端 pass，也不修改优化 pipeline。若存在 `--mlir-print-ir-tree-dir`，为本次调用分配独立目录，采集嵌套目录中本次写出的 MLIR。

文件树中的完整模块按 saved snapshot 分析，不伪造 After banner；原始 stdout/stderr 中的 Before/After 仍按实际 banner 区分。采集目录在正常结束和异常时清理；目录深度、文件数、读取字节均有限制，超限记录缺证，不把截断文件作为完整证据。具体工具能输出哪些后端结构仍必须由下一次真机产物确认。

### 3. 分离帮助查询

`--help`、`--help-hidden`、`--version`、`-h` 原样转发，不注入编译选项，不计入编译 invocation，不再产生缺少 MLIR 输入的假告警。能力探测结果依旧按工具路径和工具内容哈希缓存。

### 4. 功能 PASS 与模式认证分开退出

`bash scripts/coverage-backend-verify.sh` 仍固定只跑 Neg、Matmul 共 40 例，不接受扩大范围的参数。本轮入口额外要求：两项标签的 compilation 和 execution_validation 必须都通过，且所选算子功能审计通过。

独立门禁写入 `backend-pattern-validation.json`，记录原覆盖报告哈希，不修改已经进入审计哈希的 `suite-summary.json`。如果仍是 40 例功能 PASS、两个标签缺证，则终端明确显示模式认证 FAIL，整个入口返回非零；外层脚本仍会尝试上传结果，方便继续定位，不会再以退出码 0 暗示补证成功。

## 发布与结果边界

本机静态与回归验证通过后发布新分支，再在真机执行同一个定向入口。不运行其他算子，不更改历史报告。历史叠加编译/执行覆盖当前仍为 65/71（91.55%）；本轮代码完成不意味着已经提高到 67/71。共同确认、同版本全量冻结验收与性能验收也不由这次采集修复替代。
