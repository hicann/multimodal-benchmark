## 修复与交互调整

1. 修复 `anchors.score_per_operator` 的数据完整性缺口：已有基准时，部分测速缺失的全对算子也可能生成性能分。现在要求全部用例有测速，否则返回空分与缺失数量。增加“已有锚点 + 部分测速缺失”的回归测试。这是代码审查发现的边界问题，本次真机 20 用例测速完整，不受此问题影响。
2. Results API 新增 `performance`：有效测量数量、缺失数量、几何平均加速比、波动用例和配置阈值、任务内分数基准与不可跨任务比较标识。无效/非有限/非正测速不进入摘要。OpenAPI、快照与生成的客户端类型同步更新。
3. 上传页在校验成功后才展示算子与模式，错误先给中文处理办法，具体规则与原文按需展开；提供示例包与清晰的执行服务门禁。
4. 结果页先展示通过情况与报告入口；运行记录、指纹、恢复与文件哈希放到次级入口；标准模式直接显示提交/参考耗时和加速比，并提供波动用例筛选。结束的任务隐藏取消按钮，功能检查明确显示未测性能。
5. 算子目录与使用指南按编写实现、打包、选择模式、阅读结果组织；主导航使用中文任务名称，移动端全部入口可见。
