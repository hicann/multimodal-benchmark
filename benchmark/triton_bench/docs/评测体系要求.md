Triton Benchmark 评测体系建设
1. 概述
1.1 项目背景及开发内容
1.1.1 研究背景
Triton 是 AI 编译器和高性能算子开发的重要编程接口，承担算子表达、编译优化和硬件能力释放等关键功能，是连接上层模型应用、算子开发生态和底层硬件资源的重要支撑。随着 Triton 生态持续推进，不同硬件平台和编译器实现正在加速支持，编译器的功能完备性和综合性能成为衡量其成熟度的两个基础维度。建立统一的 Triton 编译器评测体系，对于引导编译器质量持续提升、促进算子开发生态发展具有重要意义。
现有 Triton 编译器评测多以内部测试用例和单点性能测试为主，已初步形成基础测试能力，但缺少统一口径、可复现规则和标准化的评测流程。本项目将在现有基础上完善评测体系、测试数据和运行机制，形成覆盖功能完备性验证、综合性能评估、结果追溯和榜单展示的综合评测能力。相比面向单点算子性能的内核代码评测工作，本项目更加面向 Triton 编译器整体成熟度评价的建设需求，重点建设标准化评测规范、可复现测试集和持续运行的评测平台。
基于上述基础，本项目拟围绕“面向 Triton 编译器的功能完备性与综合性能评测体系”开展建设，形成“评测规范定义标准、测试集生成支撑验证、评测平台承载运行”的项目成果结构，推动 Triton 编译器评测从分散测试用例扩展为标准化、可持续的综合评测体系。
1.1.2 研究内容
本项目围绕评测体系、基准测试数据和评测平台工程三个方面，重点开展三方面研究。
1）基于统一规范与运行规则的评测体系构建方法
面向 Triton 编译器评测的标准化需求，建立基于统一规范与运行规则的评测体系构建方法。项目将编制评测规范（Specification），定义目标问题与评测边界、语言特性覆盖维度、合法输入与排除规则和结果解释边界；形成统一数据格式、统一运行规则（硬件与软件版本、编译选项、warmup 与统计口径）、统一报告口径与版本规则；建立 Coverage 与 Performance 评分机制，形成可由脚本自动计算的量化得分，并对每个 case 开展重复测量、声明波动区间、保存原始日志，支持跨编译器版本对比，识别性能提升与回归。
2）基于语言特性覆盖与性能负载的基准测试集生成方法
面向功能完备性与综合性能两类评测需求，研究基准测试集生成方法。项目将结合 Triton 语言特性、算子组合、dtype、shape、控制流和优化 pattern 建立覆盖维度模型，功能完备性测试集采用参数化生成与覆盖引导生成相结合的方式构建，综合性能测试集结合典型算子负载构建，每个 case 输出覆盖标签；发布 case 全部冻结存档并附 seed、参数与版本元数据，保证评测阶段完全可复现，生成过程保留日志与 corpus 演化记录以供审计。测试集规模不少于 1000 个 case，覆盖双方共同确认的 Triton 核心语言特性清单比例不低于 90%。
3）面向持续运行的评测平台与工程资产建设
面向评测体系持续运行需求，建设评测网站、自动化工具链与榜单机制等工程资产。项目将开发自动化执行脚本与评分工具，建立结果提交模板与提交流程、标准化报告与榜单展示，形成版本发布、case 治理与结果提交的运行机制，并交付运营计划，支撑评测体系的长期运营和多方参与。	
1.2 项目技术方法、路线及目标	
1.2.1 研究方法和技术路线
本项目以 Triton 编译器为评测对象，构建“规范—生成—运行”三层技术架构。规范层（Specification）负责定义目标问题与评测边界、合法输入与排除规则和结果解释边界，解决评什么的问题；生成层（Generator）负责构建覆盖功能完备性与综合性能两类需求的测试集，解决用什么评的问题；运行层（Run Rules / Report）负责固化运行规则、统计口径、报告格式和榜单展示，解决如何持续运行的问题。三者共同形成从测试集生成、自动评测、结果报告到榜单发布的闭环。
1）在评测规范方面，项目将建立语言特性覆盖维度模型、指标口径定义和标准化报告机制。通过对 Triton 语言特性、算子组合、输入特征和优化 pattern 进行建模，确定覆盖维度与合法输入边界；以覆盖率与性能得分作为评测结果的核心衡量指标。
2）在测试集生成方面，项目将围绕功能完备性与综合性能组织测试数据。功能完备性测试集通过覆盖维度建模与参数化生成形成，综合性能测试集结合典型算子负载与覆盖引导生成形成，全部 case 冻结存档、附元数据并统一纳入测试集组织规范。
3）在平台机制方面，项目将基于评测结果构建标准化报告与榜单体系，建立结果提交与版本发布机制，实现评测体系的持续运行。
1.2.2 研究目标
本项目总体目标是形成一套 Triton 编译器评测体系、一系列可复现测试集和一个承载评测运行的平台原型。
1）形成一套 Triton 编译器评测体系
建立评测规范、统一数据格式、统一运行规则、评分机制和标准化报告模板，支撑功能完备性、综合性能、结果可追溯性等维度评价。
2）发布覆盖功能完备性与综合性能的测试集
围绕功能完备性与综合性能两类评测需求建设测试集，规模不少于 1000 个 case，覆盖双方共同确认的 Triton 核心语言特性清单比例不低于 90%，全部 case 冻结存档、附覆盖标签与生成元数据，统一纳入测试集组织规范。
3）实现一个承载评测运行的平台原型
集成结果提交、自动评分、报告生成和榜单展示等能力，形成从结果提交到榜单发布的全流程自动化平台，并交付支撑长期运行的运营计划。
