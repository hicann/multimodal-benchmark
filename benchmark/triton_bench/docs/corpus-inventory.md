# 测试集生成策略与题目清单（v0.4）

**这份文档讲两件事**：

1. 240 道题是**怎么出出来的**——出题的思路、每个角度的取值、怎么挑选、怎么把关；
2. 14 个算子**各自配了哪些题**——形状、数据类型、参数、数值、规模的完整清单。

读者不需要了解任何代码知识。文中所有数字都来自冻结的题库文件本身，
不是估计值。

---

## 一、先说清楚：题库长什么样

当前版本 **v0.4**，共 **240 道题**，覆盖 **14 个算子**，分成 **12 个类别**
（比如"逐元素计算"类、"归一化"类、"矩阵乘"类）。每个类别固定 20 道题；
一个类别里有两个算子的（逐元素类有 Exp 和 Gelu，归一化类有 Softmax 和
RmsNorm），20 道题平分，一边 10 道。

每道题就是一张"考卷"，上面写清楚了五样东西：

- **算什么**：哪个算子（比如 Softmax）；
- **输入长什么样**：形状（比如 4×16×64 的三维张量）、数据类型
  （比如 float32）、数值怎么分布（常规随机数？全零？超大值？）；
- **参数是什么**：比如 softmax 沿哪一维算（第 0 维？中间维？最后一维？）；
- **内存怎么摆**：输入数据是紧密排列的，还是跳着放（考验实现怎么处理
  跨步读取）；
- **时间限制**：小题 60 秒，大题 90～120 秒。

另外每道题还带一个**随机种子**——同一个种子永远造出一模一样的输入，
所以任何人任何时候重跑，考的都是同一份数据。

## 二、出题的六个角度

一道题的"难度"和"考点"由六个维度决定。这六个角度是**真刀真枪落在
题库里的**，不是纸面设计（历史上"数值分布"和"内存摆放"两个角度曾经
只在出题工具里存在、写进题库时被丢掉，等于六维实际只有四维——v0.4
起这两个维度真正进入每道题的定义里）。

### 1. 形状长相

| 长相 | 例子 | 考什么 |
|---|---|---|
| 一维长条 | [1024] | 最简单的一维并行 |
| 二维方阵 | [512, 512] | 行列分块 |
| 二维细长条 | [4096, 64] 或 [128, 2048] | 长宽比悬殊时按行还是按列切 |
| 三维立方 | [40, 40, 40] | 多维网格调度 |
| 四维 / 五维 | [2,4,8,16]、[2,4,4,4,4] | 高维下标分解（v0.3 从没考过五维，v0.4 补上） |
| 标量（零维） | [] | 最极端的退化情况（只有 ArgMax 支持） |
| 非整块 | [1000]、[99971] | 元素总数不是 1024 的倍数——处理块必须考虑"最后一小块不满"的边界 |

### 2. 规模大小（性能赛道的关键）

| 档位 | 元素数量 | 用意 |
|---|---|---|
| 小 | ≤ 4 千 | 启动一次计算引擎的固定开销占大头——测"轻量任务谁更快" |
| 中 | 4 千 ~ 25 万 | 常规负载 |
| 大 | 25 万 ~ 200 万 | 开始考验真正的并行效率 |
| 超大 | ≥ 200 万（最大 419 万） | 性能赛道主战场——纯 Python 写的实现在这里会直接超时出局 |

v0.3 的题最大只有 4 千个元素，"快慢"测的其实是启动开销；v0.4 每个算子
四个档位都有题。

### 3. 数据类型

每个算子用它支持的全部类型出题：float32（精度基准）、float16（尾数窄，
容易掉精度）、bfloat16（尾数更窄但表示范围大）、int8 / uint8 / int16 /
int32 / int64（整数语义，要求一字不差）。整数题是**精确判卷**——差一点
都算错；浮点题按精度分档放宽。

### 4. 参数变体

每个算子的参数取"默认档 + 变化档"。最关键的例子：**沿哪一维计算**
（dim）。v0.3 的 softmax 三道题的 dim 全在最后一维——一个完全无视 dim
的偷懒实现照样全对。v0.4 里 dim 横跨**首维、中间维、末维**，偷懒实现
必错。其他例子：Gelu 的 tanh 近似开关、ArgMax 的 keepdim 开关、
矩阵乘的分组方式（3 组 vs 8 组）、CrossEntropyLoss 的归约方式
（平均 vs 求和）、Transpose 的置换方式（交换首尾维 vs 轮转）。

### 5. 数值分布

| 分布 | 内容 | 考什么 |
|---|---|---|
| 常规 | 标准随机数（约 -3 ~ +3） | 基本功能 |
| 全零 | 整个输入都是 0 | 退化情况：分母会不会是 0？指数会不会溢出？ |
| 一半零 | 后半段全 0，前半段正常 | 稀疏情况：会不会把 0 当特殊值漏算 |
| 超大值 | 数值放大 20 倍（约 ±60） | 溢出与数值稳定：先减最大值再做指数的"稳定技巧"此时才见真章 |

超大值只对 float32 和 bfloat16 出题——float16 的表示范围装不下
中间计算结果，会冤枉实现。

### 6. 内存摆放

输入张量在内存里是**紧密排列**还是**跳着放**（每隔一个位置放一个数，
逻辑内容完全一样，但存储位置不连续）。跳着放的输入考实现两件事：
要么正确处理步长信息，要么先老老实实把数据聚合一遍——直接假设
"数据都是连续的"会读错答案。

## 三、出题流程：先摊开、再挑选、后把关

### 第一步：摊开候选池

不是直接决定"出哪 240 道"，而是先把 14 个算子的六个角度**排列组合**，
生成一个约 **2300 道**的候选池。每道候选生成时就检查合法性
（维度数在算子支持范围内、参数取值合法——比如矩阵乘的分组列表
之和必须等于行数），不合法的当场丢弃，绝不带病进入下一步。

### 第二步：按覆盖挑选

从 2300 道里挑 240 道，规则分三层，**覆盖优先于数量**：

1. **先保证每种"考法"都有人盯着**——我们维护一张 55 条的"语言能力
   点"清单（下文第五节），逐条检查题库里有没有能考它的题，没有就从
   候选池里挑一道最便宜的补上；
2. **再保证每个算子不偏科**——每个算子在四个规模档、每种数据类型上
   至少各有一道题，防止"覆盖了考法但只剩单一形态"的畸形题库；
3. **最后补足数量**——轮着给每个类别加题，每次优先挑能带来"这个算子
   还没考过的考法"的题，避免重复考同一个点。

只差随机种子的两道题算同一道（去重），不会用不同的种子充数。

### 第三步：质量把关（冻结前的门禁）

挑出来的每道题都要过三关，**过不了的当场剔除并记录原因**：

1. **标准答案算得出来**——参考实现在这道题上能正常跑完。参考实现
   是评测方的资产，它跑不动的题进题库，考场上就会变成"题目本身
   报错"，锅却记在被测方头上；
2. **答案稳定**——同一个参考实现连算两遍，结果必须完全一致。答案
   自己都在变的题没法判卷；
3. **答案正常**——标准答案里不允许出现无穷大或 NaN，那是锚点本身
   不可信。

v0.4 这 240 道题**全部通过三关，零剔除**。

### 第四步：锁定

题目定稿后，给每道题算一个指纹（内容改一个字指纹就变），整份题库
再算一个总指纹。每次开考之前系统先核对指纹，对不上直接拒绝开跑
——谁（包括我们自己）偷改题目都会当场暴露。

## 四、题目编号怎么读

编号格式：`算子-数据类型-规模序号`。例如 `softmax-bf16-S128`：

- `softmax` —— Softmax 算子；
- `bf16` —— bfloat16 类型；
- `S128` —— 小规模，第 128 号候选。

规模字母：S=小（≤4 千）、M=中、L=大、X=超大（≥200 万）。

## 五、能力点清单：55 条 + 7 条暂缓

"语言能力点"就是这道题**逼着实现用上什么本事**，比如"带边界掩码读
内存""沿中间维做归约""处理非连续输入"。每道题按它的定义自动打上
标签（同一道题谁来看标签都一样，不受任何实现影响），v0.4 的 240 道
题**覆盖了 55 条能力点中的全部 55 条**。

另有 7 条能力点明确**暂不纳入考核**（不算在 55 条的分母里），原因
写清楚放在清单里，比如"原子加法"——当前 14 个算子里没有一个需要
它，硬放进分母只会让覆盖率数字变虚。等收录了需要这些能力的算子
再把它们移进来。

## 六、判卷怎么保持公平

- **整数题精确判**：一字不差；
- **浮点题两把尺子**：误差"相对比例"或"绝对大小"**任意一把**在界内
  就算对（旧规则两把同时达标才算对，会在"答案本身接近零"的题上
  冤枉更精确的实现——实测纠正）；另按业界通行口径逐个元素核对
  （误差 ≤ 绝对限 + 相对限×标准值）；
- **分数旁边永远印着覆盖率**：只交 1 个算子也能在已交部分拿高分，
  所以"提交覆盖 8/14 个算子"必须和分数同屏出现；
- 每轮成绩旁边还有两个"考法达成"数字：题库出了多少种考法、
  这轮真正考过了多少种。

## 七、每类算子搭载了哪些题

**总账**：12 个类别 × 每类 20 题 = 240 题。两个类别里各有两个算子，
20 题基本平分（差一题给排前的算子）：逐元素类 = Exp 11 题 + Gelu 9 题；
归一化类 = Softmax 11 题 + RmsNorm 9 题。其余 10 个类别各 1 个算子、
各 20 题。

**全库分布**：

| 维度 | 分布 |
|---|---|
| 规模 | 小 164 / 中 47 / 大 15 / 超大 14（大+超大共 29 题，是性能赛道的重载题） |
| 数值 | 常规 123 / 全零 44 / 一半零 50 / 超大值 23 |
| 内存摆放 | 跳着放（跨步输入）28 题 |
| 能力点 | 55 种考法全部有题盯着；最少的两种是 int16（2 题）和 uint8（3 题）——冷门类型按"至少一个代表"的规则保底 |

下面逐类列出。规模列的 S/M/L/X 对应上面的小/中/大/超大；
"数值"列的数字是四种子（常规/全零/一半零/超大值）各几题。

考"门控线性单元"——一道题里融合了sigmoid、乘法、按维拆分三种操作。

| 算子 | 题数 | 形状 | 数据类型 | 沿哪维拆 | 数值 | 跨步 | 规模 |
|---|---|---|---|---|---|---|---|
| SwiGlu | 20 | 一维 [1000]、[1024]、[4194304]；二维 [32,32]、[1000,1000]、[128,2048]；三维 [40,40,40]；四维 [4,8,16,32]、[2,4,8,16]；五维 [2,4,4,4,4] | fp32 / fp16 / bf16 | 首维 11 题、中间维 6 题、末维 3 题 | 9/3/5/3 | 3 | S15 M3 L1 X1 |

## 八、怎么重新生成 / 放大规模

题库重建只需一条命令，规模是一个旋钮：

```bash
python scripts/build_corpus_v2.py --per-category 20   # 当前 v0.4
python scripts/build_corpus_v2.py --per-category 40   # 扩大一倍
```

重建时会重新走"摊开→挑选→把关→锁定"全流程，指纹随之更新。
当前 14 个算子、每类 20 题是"先验证出题质量"的选择（2026-10-09
决定）；后续算子从 14 个扩到约 200 个、题目从 240 涨到 1000+，
用的还是同一条流水线，只改参数不改编代码。
