# 测试集是怎么出出来的：出题方法说明

**一句话**：先给每个算子把所有可能的考法都摆出来，再照着一张
"该考什么"的清单从中挑题，挑出来的题经过三道质量检查后锁死存档。

本文讲的是方法本身；每个算子实际分到了哪些题，见姊妹篇
`docs/corpus-inventory.md`（题目清单，全部真实数字）。

---

## 一、为什么不能"直接出题"

最初的做法很简单：每个算子按配方出 5 道题，形状、类型、参数轮流换着来。
这个做法有两个躲不掉的问题，都是实际发生过的：

**问题一：看不见自己的盲区。** 轮换是均匀的，但它不知道自己漏了什么。
真实案例：softmax（按一维做归一化的算子）的三道题，"沿哪一维算"
这个参数恰好全落在最后一维。于是一个完全无视这个参数、永远按最后一维
算的偷懒实现，在我们的题库里能拿满分。题目出了，等于没出。

**问题二：数量堆不出质量。** 把每类从 5 道加到 50 道，结果只是
同样几种考法的重复堆叠。考法的种类没有变，多出来的题都是陪跑。

所以现在的做法分四步：**先摊开、再挑选、后把关、最后锁死**。

## 二、第一步：摊开

不直接决定"出哪 240 道"，而是先把 14 个算子的出题角度排列组合，
生成一个大约 **2300 道**的候选题库。组合的原料是六个角度：

| 角度 | 取值举例 |
|---|---|
| 形状长相 | 一维长条、方阵、细长条（长宽比悬殊）、立方体、四维、五维、零维（单个数）、元素数不是整块的奇数尺寸 |
| 规模 | 小（几千个元素）→ 中 → 大 → 超大（四百万个元素） |
| 数据类型 | 三种浮点（float32 / float16 / bfloat16）加五种整数，每个算子用它支持的全部 |
| 参数 | 默认值加上变化值——特别是"沿哪一维算"要覆盖首维、中间维、末维 |
| 数值分布 | 常规随机数、全零、一半为零、数值放大 20 倍（考验溢出处理） |
| 内存摆放 | 数据紧密排列，或跳着放（考验步长处理） |

每道候选题在生成的**当下**就检查合法性：维数必须在该算子支持的范围内，
参数取值必须合法（比如矩阵乘的分组列表加起来必须等于行数，维度的序号
必须在范围内）。不合法的当场扔掉，不带病进入下一步。

> 注：数值放大 20 倍的题只对 float32 和 bfloat16 出——float16 能表示的
> 数值范围装不下中间计算结果，硬出这种题会冤枉实现。

## 三、第二步：挑选（本文的重点）

2300 道候选里挑 240 道，规则分三层，**覆盖优先于数量**：

### 第一层：先保证每种"考法"都有人盯着

我们维护着一张 **55 条的"考法清单"**。所谓考法，就是一道题逼着实现
用上什么本事，比如"元素总数不是整块时，块尾要带边界保护""沿中间维
做归约""输入数据跳着放时要正确处理"。清单里每一条都写明它是什么、
怎么从题目定义判断这道题考不考它。

挑选时逐条过清单：某种考法一道题都没有，就从候选里挑一道最便宜的
（优先小规模、常规数值的）补上。前面说的 softmax 维度盲区就是这么堵上的
——现在 softmax 的题横跨首维、中间维、末维，偷懒实现必错。

另外有 7 条能力（比如"原子加法"）**明确不放进清单**，原因写在清单里：
当前 14 个算子没有一个用得上，硬放进分母只会让覆盖率数字变好看、
实际是空的。等以后收录了需要这些能力的算子再放进来。

### 第二层：再保证每个算子不偏科

只满足考法清单还不够——可能出现"考法都覆盖了，但矩阵乘只剩一种形状"
的畸形题库。所以加一条硬规则：**每个算子在每一档规模上、在它支持的
每一种数据类型上，至少要有一道题**。

### 第三层：最后补数量

前两层挑完大约一百多道，剩下的名额按类别轮着补。每补一道，优先选
能给这个算子带来"还没考过的考法"的题——实在没有新的，才选便宜的。
另外，两道题如果只差随机数种子（其他全部一样），算同一道，不会
用换种子的办法充数。

## 四、第三步：把关

挑出来的题要过三道检查，**过不了的当场剔除并记录原因**（写进题库
文件的"剔除记录"栏，为什么没这道题永远可查）：

1. **标准答案算得出来**——参考实现在这道题上能正常跑完。参考实现
   是评测方自己的资产，它都跑不动的题进了题库，考场上就会变成
   "题目本身报错"，责任却记在被测一方头上；
2. **答案稳定**——连算两遍，结果必须完全一致。答案自己都在变的题
   没法判卷；
3. **答案正常**——标准答案里不允许出现无穷大或"不是数"（NaN）。

v0.4 的 240 道题全部通过三道检查，零剔除。

## 五、第四步：锁死

题目定稿后，给每道题算一个指纹（题目内容改一个字、指纹就变），
整份题库再算一个总指纹。每次开考之前系统先核对指纹，对不上直接
拒绝开考——谁（包括我们自己）偷改题目都会当场暴露。

**每道题的"考法标签"也一起锁死。** 标签有一个重要的规矩：它只从
题目本身的定义（形状、类型、参数、数值、摆放方式）算出来，
**跟谁来答题无关**——不管是哪个提交方、哪个编译器版本，同一道题的
标签永远一样。这条规矩保证了三件事：

- 覆盖率的分子分母不会偷偷漂移；
- "缺哪种考法"能直接反推出"该补哪类题目"（挑选第一层的依据）；
- 出争议时，"这道题考什么"不依赖任何一方的说法。

## 六、判卷怎么保持公平

出题公正之外，判卷也要公正，两处规则专门防冤案：

- **浮点题两把尺子**：误差的"相对比例"或"绝对大小"**任意一把**在界内
  就算对。旧规则要求两把同时达标，会在"标准答案本身接近零"的题上
  冤枉更精确的实现（实测发生过：一份比标准答案更准的实现被判错）；
- **另加一道逐元素核对**：每个位置的误差不超过"绝对限 + 相对限 ×
  标准答案的值"。这是业界通行的判法，对接近零的答案有正确的行为。

整数题没有这些宽容：一字不差才算对。

## 七、这套方法的自我改进（下一步）

现在"哪里没考到"是出题前算出来的。下一步是把**考试结果**接回出题：
哪种考法上错的人多，就往哪种考法上加题加密——"哪里错得多，
哪里就多考"。数据是现成的：每道题的考法标签和每道题的成绩存在
同一个数据库里，差一条统计命令。

## 八、规模是一个旋钮

这次出的是 12 个类别 × 每类 20 道 = 240 道，目的是先验证出题质量。
验证的结果：55 种考法全部有题盯着；新题库第一次上真机就抓出两个
真实短板——**五维形状的题**让样例提交现了原形（它写死了最多处理
四维，旧题库从没考过五维，所以一直没暴露）；**零维单个数的题**
让纯 Python 手写的对照实现一跑就崩（旧题库根本没有这种题）。
这正是想要的效果：**题目比以前更难糊弄了**。

以后扩大规模（任务要求最终 1000 道以上）不需要改方法，改一个数字
就行——每个类别的题数从 20 调到 40、80……瓶颈在算子种类
（现在 14 个，选型池约 200 个），不在出题管线本身。

具体命令（在项目根目录）：

```bash
python scripts/build_corpus_v2.py --per-category 20   # 当前规模
python scripts/build_corpus_v2.py --per-category 40   # 扩大一倍
```

重建会完整重走"摊开→挑选→把关→锁死"四步，指纹随之更新；
每个算子实际拿到哪些题，用下面这条命令随时对账：

```bash
python scripts/corpus_inventory.py
```
