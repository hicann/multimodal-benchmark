# v0.11：六项实现证据闭环

本版本继续落实 `评测任务.md` 的覆盖引导生成、冻结存档、可复现和可审计要求。
上一版对六项标签直接拒绝计分，只指出证据缺口，尚未提供闭环。本版本加入对应实现、实际启动参数与内存绑定采集，以及专门的编译结构判据。

## 输入与版本

- 新语料目录：`corpus/v0.11-implementation-candidates`。
- 新提交目录：`examples/coverage-v11-ascend-submission`。
- 保留 v0.9 的 68 × 20 = 1,360 个用例，也保留 v0.10 的全部 17 个补充用例。本次不增加或删除输入用例。
- 仍为 74 个算子、1,377 个用例；固定 71 项 active 标签，静态覆盖 67/71 = **94.37%**，90% 的离散门槛仍为 64/71。
- v0.9、v0.10 的清单、参考文件、历史资产指纹与历史提交样例保持原样。评测框架改变后旧资产不能由新框架直接复认证，需要检出其对应历史提交。
- 不改变容差、参考结果、标签定义、分母和双方共同确认的要求。`agreement_state` 仍为 `AWAITING_JOINT_CONFIRMATION`，不能据此宣布任务书最终验收。

## 六项逐项证据

| 标签 | 实现载体 | 编译结构与绑定判据 |
|---|---|---|
| `FA-PAT-MASK-TAIL` | 新的 Neg 分块内核；复用现有 `[2,4097]` 输入 | N、步长、块长和实际 grid 一致；尾块非空；活跃的边界比较同时约束实际输入 load 和输出 store |
| `FA-PAT-VEC-LOAD` | 同一 Neg 内核；复用现有连续大内维输入 | 连续、单位步长的访问进入输出数据流；还必须在降低后的 IR 中找到实际向量内存 load。仅 tensor 形状的 `tt.load` 不足以计分 |
| `FA-PAT-COALESCE-GATHER` | 现有 Gather 的整行预取与 `tl.gather` | 主数据的连续行加载与真实索引输入分别进入活跃 gather，结果进入最终输出；实际列数、行 grid 与输入相符 |
| `FA-PAT-TILE-GEMM` | 现有 Matmul 的 16×16×32 分块 dot 循环 | 核对实际 tile、M/K/N 和 grid，输出依赖循环中的 dot；降低后的 dot 两个操作数必须依赖明确的共享内存分配。只出现 dot 或无关的共享内存分配均不给分 |
| `FA-PROG-GRID4D` | 新的四维 Neg 内核；复用现有 `[2,3,5,17]` 输入 | 逻辑轴 0/1 打包到物理 z，轴 2 映射到 y，轴 3 在 x 内分块；核对实际四维 shape、常量及物理 grid，并要求三个 program_id 参与实际地址计算 |
| `FA-FUSE-INTERM-ELIDE` | 新的单核 MaskedSoftmax；复用现有小归约轴输入 | 两个真实输入进入掩码→exp/归约→归一化的 SSA 依赖；仅一次启动、仅一次最终输出 store；所有全局 load 来源于输入，全局 store 只指向返回输出，输出存储不得与输入别名；拒绝 scratch、外部调用及第二次启动 |

GRID4D 遵循现有定义“rank≥4 输入的 grid 映射”。它不声称存在四轴原生启动。
报告逐条记录 `logical_shape`、`physical_grid`、`native_grid_rank=3` 以及映射方式。
例如逻辑 `[2,3,5,17]` 对应物理 `[1,5,6]`。四维坐标分解被编译器等价化简后，仍可通过已审阅源码、绑定参数和活跃地址数据流证明映射，无需强迫保留无用除余操作。

## 信任与失败边界

采集器只包围正确性执行，记录真实 JIT 返回的源代码、IR、后端产物、参数与 constexpr、输入和输出张量身份及存储身份；不保存原始内存地址。相同存储的不同视图共享存储身份，可以检测别名。采集完成后恢复 JIT hook，性能计时不带该 hook。

六项判据使用**评测方冻结的已审阅内核源码**作为结构证明的起点，再与真实参数、真实 IR 数据依赖和内存访问核对。当前识别范围是上述有限内核，不是对任意提交的通用程序证明；更换合法实现但未被识别时会明确保留未验证。被测提交自己的注释、标签、声明、关键词或一份死代码副本不能替代证明。

当前向量访存适配识别 LLVM 的向量 load / MLIR vector load；共享内存适配识别 TritonGPU 的 `ttg.local_alloc` / `ttg.memdesc` 到 dot 的依赖。不同昇腾版本可能使用其他等价降低形式。**若该后端没有输出这些形式，本轮相应标签必须保持未验证**，报告指出所缺结构；需依据实际归档产物补充审阅过的适配，不从名称猜测内存空间，也不降格为“有 dot 就算共享分块”。这是后端适配的不确定性，不能提前宣称六项在真机全部成立。

此前“67−6=61 项，因此实现证据最多 85.92%”是旧版六项无判据时的上限。新版不再有这六项直接拒绝造成的固定上限，但最终覆盖率仍取决于本次真机见证，不预填 67/71。

## 三类结论与性能收益

1. **本机静态覆盖**：标签并集 / 固定 71 项，当前 67/71。不是各算子覆盖率的平均。
2. **编译见证覆盖**：同一环境下，有完整编译产物、通过身份审计且满足专门判据的标签并集 / 71。
3. **执行验证覆盖**：编译见证再叠加真实同步执行 PASS、独立 CPU/NPU 参考门禁与运行完整性审计；仍除以 71。

优化 Pattern 的结构实现、数值正确和性能收益分别披露。本轮编译或正确性覆盖不能证明提速；既有 `scripts/probe_validation.py` 的对照探针可用于独立性能实证。历史探针的提速结论不会自动转移到本版本提交或本次编译器。未对本次实现进行对照计时的性能结论始终为 `NOT_ESTABLISHED`。

## 验证与真机入口

本机测试包含六项正反例、实际新内核源码的 CPU 张量模拟（四维寻址、连续/跨步输入、各归约轴及 bool/int8/uint8 掩码）、启动参数及存储别名采集。合成 IR 只测试判据，不构成任何真机覆盖证据。

真机测试额外复用现有的六类载体，实际编译、运行并断言六项见证；如后端降低尚未适配，会显式失败，并保留产物供分析。CPU 环境跳过这些设备测试。

本机先验：

```bash
python scripts/check_coverage_readiness.py
```

发布到远程分支后，真机全量入口：

```bash
cd "$HOME/triton-eval-v07" &&
git fetch origin refs/heads/codex/v09-generation-validation &&
git switch --detach FETCH_HEAD &&
git log -1 --oneline &&
bash scripts/coverage-suite-verify.sh
```

该入口固定使用 v0.11 新语料和新提交，先验证静态门禁，再运行并归档、审计编译和执行覆盖。
具体提交是否已上传必须以推送结果为准，不能仅凭本地提交判断。没有 NPU 实测前，本版本编译和执行状态均为 `NOT_RUN`。
