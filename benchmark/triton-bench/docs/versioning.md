# 测试集版本与发布规则

任务书要求"形成版本发布、case 治理与结果提交的运行机制"。本文件是
版本发布机制的规则文档；工具见 `scripts/release.py`，勘误见
`docs/errata.md`。

## 版本对象：测试集五轴组合

"一个版本"不是单个文件，而是**五个独立版本轴的快照**——它们任何一个
变化都可能改变同一份题的分数：

| 轴 | 存放 | 2026-10-15 现值 |
|---|---|---|
| 测试集（corpus） | `corpus/<目录>/manifest.json` | v0.5-cov20-frozen（289 用例） |
| 评测规范（spec） | `spec/spec.yaml` | 0.1-mvp |
| 评分器（scorer） | `spec/spec.yaml` | 0.2.3 |
| 容差表（tolerance） | `spec/tolerance.yaml` | 1.2 |
| 能力点清单（FA） | `spec/feature_atoms.yaml` | 1.1-fusion |

每份评测报告强制披露其中三轴（spec / corpus / scorer）——"我考的是
哪套卷"必须能被精确回答。

## 指纹与版本的分工

- **指纹**（manifest 哈希 + 逐用例内容哈希）回答"**内容是否被改过**"
  ——评测启动时重算比对，被改即拒绝运行。
- **版本**（git 标签）回答"**这是哪一版**"——对外可引用的名字。
  两者互补：指纹是身份证，版本是名字。

## 发布 = 打标签

**打标即发布**。发布一个版本 = 在冻结该语料的提交上打一个 annotated
git 标签 + 一页发布说明（`docs/releases/corpus-v{X}.{Y}.md`）。

- 标签名从语料目录名推导：`v0.5-cov20-frozen` → `corpus-v0.5`
  （目录名后缀是生成策略描述，不进标签）；
- 发布前校验（脚本自动执行，任一失败拒绝发布）：工作区干净、清单
  指纹可重算、演化文档与再生成一致、生成日志存在、测试全绿；
- 发布说明内容：五轴快照、清单哈希、生成器提交号与构建环境、与
  上一版差异（引 docs/corpus-evolution.md）、受影响勘误、验证状态。

## 版本号语义（沿用技术报告 §4.7）

- **MAJOR+1**：FA 清单变更、删除已有用例、oracle 语义变更、判定规则
  变更 → 历史分数全部作废，必须重跑；
- **MINOR+1**：纯新增用例（不改已有用例）→ 历史分数保留，标注
  "基于 vX.(k-1) 子集"；
- **tag 之前的修订**：同一版本号内的重冻结 / 修订合法（演化对照表
  如实记录差异），因为该版本尚未发布、无人基于它对外出过成绩；
- **tag 之后**：任何用例变更必须走勘误（AMEND / RETRACT）或升版本
  号，不允许静默修改——静默改等于偷偷换卷子。

## 勘误处置三分类

见 `docs/errata.md` 头部：AMEND（修正容差/参考）、RETRACT（撤销用例，
触发 MAJOR+1）、ANNOTATE（只加注不改判定）。发布说明自动收录受影响
版本的勘误条目。

## 工具轴的修订不单独打标

spec / scorer / tolerance / FA 的修订独立递增各自版本号（规范要求），
**不单独打标签**——它们的变化收录进下一次测试集发布的发布说明。
理由：单独的工具修订不构成"一套新卷子"，但必须可追溯（各自版本号
+ git 历史 + 勘误登记已满足）。

## 回溯打标

历史语料（v0.3 / v0.4 / v0.5）补打的标签锚定"**当前清单内容落地**的
提交"（`git log` 中 manifest 与现存内容一致的最近提交，**不一定是首次
提交**——v0.3 的当前清单是 schema 迁移时保留语义、重算指纹的产物，
锚点落在迁移提交而非首冻提交；v0.5 的 286→289 重冻结发生在首次
推送之前、中间版本从未入库，锚点即首冻提交）。五轴快照从锚定提交
读取；清单内记录的版本与锚定提交的版本轴不一致时，发布说明如实
注明两个记录。补录标签只为可追溯性服务，不改变"这些版本在草稿期
被消费"的历史事实（勘误按草稿期修订口径登记）。

## 发布节奏

- **项目期**：冻结即发布——每冻结一个测试集版本即打标签；
- **平台运营期目标**（技术报告 §4.12，远期口径）：测试集季度发布
  MINOR、年度发布 MAJOR；榜单月度更新；规范年度复审。

## 签名标签

技术报告选型提及 signed tag。当前阶段**暂缓**：仓库的信任根是
gitcode 推送凭证，无社区参与方时签名没有受益人；开放外部提交后
再引入（届时发布方密钥随运营计划一并交付）。
