# 覆盖维度扩展方案：算子组合（融合）与优化手法

**目的**：任务书要求覆盖维度模型从"语言特性、算子组合、dtype、shape、控制流、
优化 pattern"六个来源建立。当前已实现六个用例生成维度（形态/规模/数据类型/
算子参数/数值分布/内存布局），但"算子组合"与"优化手法"两维在能力点清单中
仅有预留标签、没有生成逻辑（覆盖度报告 2.1 的 🟡 缺口）。本方案给出这两维
的落地设计。

**范围边界**：本方案不与"测试集规模达到 1000 用例"的目标绑定——新增用例
数量以"把两维真正考察到"为准（预计 v0.5 较 v0.4 新增约 130–170 个用例），
不为凑数加量。

---

## 1. 必须遵守的现有架构约束

方案设计受以下既有机制约束，任何一条被破坏都会推翻已验证的地基：

| 约束 | 内容 | 对本方案的要求 |
|---|---|---|
| 标签纯函数边界 | 标签 = f(算子规格 + 用例六维)，不依赖任何实现，可随时重算核对 | 组合与手法两类新标签都必须仍由"规格 + 用例定义"推导，不得依赖提交方行为 |
| 数据格式不可缩水 | 用例格式字段在设计时按最终规模定义，扩充不改格式 | 新维度尽量复用现有字段（算子名、参数、六维），避免改 schema |
| 门禁在无 NPU 机器运行 | 生成与冻结在开发机执行，参考实现基于 torch，参考自检（可执行、两遍一致、输出有限）在无 NPU 环境完成 | 任何"NPU 上才能做的验证"不得放进生成时门禁，只能放入真机验证窗口 |
| 冻结与指纹 | 用例与标签随指纹冻结，改一字可检出 | 新标签进指纹；能力点清单升版 |
| 评分分母 | 功能分分母仅含"提交了实现"的算子；覆盖率分母仅含生效能力点 | 新算子/新原子进入分母的规则必须显式（见 §5.3） |
| 锚点不跨测试集版本 | 性能基准按算子在**同题库版本**内冻结 | v0.5 发布后所有算子基准需重新冻结（见 §3.6） |
| 反作弊规则 | 禁止把核心计算委托给框架内置函数、禁止主机往返、禁止自动调优 | 组合算子的判定口径需要新增决策记录（见 §3.5） |

## 2. 维度一：算子组合（融合算子）

### 2.1 建模选择：组合算子一等公民化

**结论：融合算子作为新的算子条目进入算子注册表，而不是发明"用例内描述
算子流水线"的新格式。**

理由：

1. **有现成先例**：SwiGlu 本身就是融合算子（语义族 FusedComposite），
   已经端到端走通"注册表 → 用例生成 → 打标 → 门禁 → 判定 → 评分"全
   流程。本方案只是把"融合"从单个现成算子扩展为**系统化的组合目录**。
2. **数据格式零改动**：用例仍是"算子名 + 输入输出 + 参数 + 六维"，
   组合结构登记在算子侧（注册表），用例格式不需要新字段——满足 §1 的
   格式约束。
3. **全链路免费复用**：生成、合法性校验、门禁、容差、评分、报告、两轮
   对比对组合算子与普通算子一视同仁，不需要任何新机制。

**组合结构登记**：新增一张组合表（放在算子注册模块），每个融合算子声明
其组成段落，例如：

```
组合表条目 = {
  融合算子名: LinearGelu,
  段落: [(GroupedMatmul, 单组模式), (Gelu, 直通)],
  数据流: 段1输出 → 段2主输入，
  段参数: 段2 可带自身非默认参数（如 approximate="tanh"）
}
```

组合表是**算子侧的规格**（与 cann-bench 来源目录对应的"合成规格"），
标签的纯函数推导从它出发——不依赖任何实现。

### 2.2 融合算子目录（11 个，两个来源，逐条可追溯）

**来源一（Tier 2）：由现有 14 个原语组合**——参考实现即原语参考的顺序调用，
不新写 oracle：

| 融合算子 | 组成 | 语义族 | 考察的典型收益 |
|---|---|---|---|
| LinearGelu | 分组矩阵乘（单组，即普通矩阵乘）+ gelu | FusedComposite | 收缩 + 逐元素融合：省一次全量读写 |
| RmsNormLinear | rms_norm（按行归一）+ 分组矩阵乘（单组） | FusedComposite | 归一化喂收缩：LLM 前向的典型前缀 |
| GroupedMatmulSwiGlu | 分组矩阵乘 + swi_glu | FusedComposite | LLaMA MLP 投影融合（矩阵乘 → 激活门控） |
| MaskedSoftmax | 掩码缩放（置 -inf）+ softmax | FusedComposite | 注意力掩码与归约的融合 |
| TransposeLinear | transpose + 分组矩阵乘（单组） | FusedComposite | 布局变换喂收缩：消除单独转置内核 |
| MaskedGelu | 掩码保留 + gelu（掩码外置零） | FusedComposite | 掩码与逐元素融合 |
| GatherExp | gather + exp | FusedComposite | 索引与逐元素融合 |

**来源二（Tier 1）：直接收录来源池中已存在的融合任务**（cann-bench
`tasks/` 目录实测在列，非自行设计；逐条标注来源目录与收录差异）：

| 融合算子 | 来源池任务 | 主流场景 | 收录说明 |
|---|---|---|---|
| AddRmsNorm | `tasks/level3/add_rms_norm_dynamic_quant` | 残差加 + 归一：每个 LLM 解码块各执行一次的主流融合 | 收录 add + rms_norm 主干；dynamic_quant 段随量化批次并入 |
| GroupedMatmulSwiGluQuant | `tasks/level4/grouped_matmul_swiglu_quant` | 量化推理的 MLP 投影（W8A8 形态） | 收录矩阵乘 + swiglu 主干（与来源一的 GroupedMatmulSwiGlu 同构）；量化段随量化批次并入 |
| ApplyRotaryPosEmb | `tasks/level2/apply_rotary_pos_emb` | 旋转位置编码：主流 LLM 推理的标准组件 | 全量收录（正弦/余弦查表 + 逐元素旋转） |
| MoeGatingTopKSoftmax | `tasks/level3/moe_gating_top_k_softmax` | MoE 路由门控：主流 MoE 模型的标准组件 | 全量收录（top-k 选取 + 选中位 softmax） |
| UnsortedSegmentSum | `tasks/level2/unsorted_segment_sum` | 段归约累加 | 全量收录；与并发累加手法原子互为载体（§3.2） |

Tier 1 算子按普通算子进入注册表（来源目录指向池任务）；其段落结构同样
登记进组合表（段落引用池任务的语义段，不要求段本身是已注册原语），使
融合标签的推导口径对两类算子统一。

设计规则：

- **兼容性硬约束在派生时校验**（沿用"派生即校验"机制）：段间数据类型必须
  一致或可安全提升、段 1 输出形状必须匹配段 2 输入形状约束、各段参数取值
  落在各段合法集合内；
- **遵守现有分级边界**：注册表注释已写明 FusedComposite 仅收录简单融合
  （L1–L2）；池中 L4 的注意力整体（MHA/MLA/GQA/sparse_flash_attention）
  与循环结构（GRU/LSTM）**不进本批**——它们依赖更完整的收缩原语，待本
  方案验证后另立方案；
- **来源池中已识别、本批不做的后续候选**（列出以防"来源池里其实有"的
  遗漏）：`dequant_swiglu_quant` / `quant_matmul` /
  `weight_quant_batch_matmul`（量化批次——需先定夺整数量化的精确匹配
  口径）；`foreach_addcdiv_scalar` / `foreach_norm` / `apply_adam_w`
  （优化器 foreach 批次——需先扩展输入构造支持张量列表）；
  `mish` / `sigmoid`（逐元素激活原语，组合扩容需要时再收）；
- **规模四档照常**：每个融合算子在四档规模各至少一个代表用例，参数空间
  按段展开（受兼容性约束裁剪）。

### 2.3 组合维度的标签方案

新增**融合原子**（能力点清单 1.1 版新增，随清单版本化）：

| 新原子 | 推导规则（纯函数） |
|---|---|
| FA-FUSE-2STAGE | 组合表声明两段融合 → 该算子的用例全部携带 |
| FA-FUSE-CROSS-CATEGORY | 组合表声明的两段属于不同语义族（如收缩 × 逐元素） |
| FA-FUSE-ELEM-INTRA | 组合表声明的两段同属逐元素族 |
| FA-FUSE-RED-INTRA | 组合表声明的段落含归约/归一化段 |
| FA-FUSE-INTERM-ELIDE | 两段融合的用例隐含"中间结果不出内核"考察——组合表的
  结构本身即声明，所有 2 段融合原子用例附带 |

推导全部从组合表 + 用例定义出发，不依赖实现——满足 §1 纯函数约束。
覆盖率披露同时展示：融合原子覆盖数 / 融合算子用例数，避免"融合标签只是
换个名字的算子覆盖"这类误读。

### 2.4 参考实现与门禁

- **参考实现 = 原语参考的顺序组合**（单一代码事实来源，不新写 oracle）：
  例如 LinearGelu 的参考 = 调用矩阵乘参考 + 调用 gelu 参考。参考自检
  门禁（可执行、两遍一致、输出有限）按既有机制跑组合参考。
- **容差**：组合会累积数值误差（段 1 的舍入进入段 2 放大）。处理方式沿用
  已验证的机制：先按数据类型默认档判定，**仅当真机归因证实参考自身偏差
  超过默认档时**才登记算子级覆盖（附归因证据），不做预防性放宽。
- **确定性**：组合参考中不得引入非确定性操作（如非确定的散射累加顺序），
  门禁的"两遍一致"检查会自动拦截。

### 2.5 反作弊与判定口径（需新增决策记录）

**核心决策：不强制单内核。** 融合算子考察的是"融合后的性能收益"，
提交方用单个 triton 内核实现融合、或用两个内核串联实现，均属合法——
两者的性能差距正是该维度要测量的内容，体现在加速比上，而不是判定
作弊。禁止的仍是既有规则：把任一段或整段核心计算委托给框架内置函数、
张量往返主机、自动调优。

**辅助自查命令**（validate/ingest）对融合算子按同样口径静态扫描。

### 2.6 评分与版本影响

- 融合算子按等权进入功能分（沿用决策 C7 等权），语义族归入
  FusedComposite，报告按既有分组口径出分；
- 新算子 + 新原子构成**测试集 v0.5**（v0.4 保持冻结不动）：
  - 锚点按测试集版本隔离——v0.5 发布后，各算子（含 14 个原语算子）
    的性能基准需在 v0.5 内重新冻结。**示范提交必须同步实现 11 个融合
    内核**，否则融合算子永远无基准（锚点轮的载体是示范提交，这是
    10-12 真机实测得出的结论）；
  - compare 命令要求同测试集版本（既有前置校验），v0.4 与 v0.5 之间
    不做用例级对比；
  - 未实现融合算子的提交：功能分分母仅含已提交算子（既有口径），
    报告披露未提交清单——旧提交的分数在新测试集上仍可在其提交范围内
    比较，但这是"部分覆盖"的对比，报告强制披露语句已有。

## 3. 维度二：优化手法

### 3.1 手法原子的语义定义（新的一类原子，边界必须说清）

现有 55 个生效原子全部是**正确性负载型**：用例不用该能力就无法通过。
优化手法维度引入**性能负载型**原子，语义为：

> 该用例的结构使"使用优化手法 X"与"不使用"之间存在**可测量的显著
> 性能差距**——用例谁都能算对，手法水平体现在计时上。

两条诚实性规则：

1. **标签仍是纯函数**：手法原子由"结构谓词"推导——只看算子语义族 +
   形状/规模/布局/参数，不看任何实现。例如"收缩类且元素总量 ≥ 阈值"
   即可推出"分块（tiling）收益显著"。
2. **"显著"必须真机实证**：结构谓词只是声明；每个手法原子必须配一对
   **探针内核**（朴素写法 vs 手法写法，评测方资产），在真机验证窗口
   实测收益差距，证据归档。未通过实证阈值的原子降级为"声明性考察"
   并在披露中注明（见 §3.3）——不允许没有证据的"考手法"标签装点
   覆盖率。

### 3.2 手法原子目录（11 条）与结构谓词

前五条由现有 14 个算子的参数空间即可触达；后六条依托本方案新增的融合
算子与参数变体触达。每条给出"标签由什么推导"——全部只看算子语义族 +
形状/规模/布局/参数：

| # | 手法原子 | 结构谓词（纯函数推导） | 实现侧手法 | 负载类型 |
|---|---|---|---|---|
| 1 | FA-PAT-TILE-GEMM | 语义族=收缩 且 参与元素量 ≥ 2^18 | 共享内存分块（tiling） | 性能负载 |
| 2 | FA-PAT-VEC-LOAD | 逐元素/掩码 且 连续布局 且 最内维 ≥ 4096 且可整除对齐 | 向量化访存 | 性能负载 |
| 3 | FA-PAT-MULTIPASS-REDUCE | 归约选择类 且 归约维 ≥ 2^20 | 多趟归约（单趟寄存器放不下） | 性能负载 |
| 4 | FA-CONCUR-ACCUM | Scatter(reduce="sum"，索引含重复) 或 UnsortedSegmentSum | 原子加法 / 顺序无关累加 | **正确性负载**（重复索引下累加顺序无关是语义要求） |
| 5 | FA-CTRL-STATIC-UNROLL | 分组矩阵乘 且 group_list 长度 ≤ 8 | 静态循环展开 | 性能负载 |
| 6 | FA-PAT-SPLIT-K | 收缩 且 M ≤ 64 且 K ≥ 2^16（高瘦矩阵） | 沿归约维切分并行（split-K）：M/N 并行度不足时拆 K 补 | 性能负载 |
| 7 | FA-PAT-VEC-BROADCAST | 收缩 且 带 bias 且 M ≥ 2048 | 偏置向量跨行广播驻留（bias fused GEMM 的标准手法） | 性能负载 |
| 8 | FA-PAT-MASK-TAIL | 逐元素 且 最内维 ≥ 2048 且 最内维 不整除向量宽度 | 边界掩码访存（尾部不满块） | 性能负载 |
| 9 | FA-PAT-COALESCE-GATHER | 索引类 且 索引分布限定窄窗口（新增索引分布参数变体） | 聚集访存（内存局部性） | 性能负载 |
| 10 | FA-PAT-ROW-STRIDE-VEC | 非连续布局 且 行内连续 且 行长 ≥ 2048 | 行级跨步向量化（非整体连续但行内可向量化） | 性能负载 |
| 11 | FA-PAT-SCAN-BLOCKED | 扫描类（cummin）且 规模 ≥ 2^20 | 分块两趟扫描（块内扫描 + 块间携带） | 性能负载 |

其中三条是**预留原子的转正**，转正条件本方案已满足：

- `FA-ATOMIC-ADD`（预留理由"需收录含原子归约的算子"）——实际 **Scatter
  已带 reduce 属性**，重复索引 + reduce="sum" 的用例即可定向触达原子
  累加语义，转正为上表的 FA-CONCUR-ACCUM；收录 UnsortedSegmentSum 后
  该原子获得**第二个载体算子**（同一手法跨算子验证，避免"单算子特例"）；
- `FA-CTRL-STATIC-FOR`（预留理由"实现侧选择，用例层不可定向"）——
  group_list 长度本身是用例定义的一部分，"小循环次数可静态展开"可由
  用例推导，转正为 FA-CTRL-STATIC-UNROLL（语义从"用了静态循环"改为
  "该用例使静态展开可行且有收益"，与手法原子口径一致）。

另有一个顺带项：`FA-SHAPE-BROADCAST`（预留理由"maximum 参考输入当前
同形"）——扩展 maximum 的输入构造支持广播形状即可转正，与本方案同一
工作流，预计 5–10 个用例。

**一条明确的排除**（防止"主流手法为什么没收"的疑问）：软件流水
（num_stages 多级缓冲）**不设原子**——决策记录 C11 已实测确认
`num_warps` / `num_stages` 在昇腾平台上不生效，该手法在本平台没有可
测量的收益差，设了也是装饰性标签。待平台支持变化后再评估。

### 3.3 收益实证机制（手法维度的诚实性核心）

1. **探针对是评测方资产**：每个性能负载型手法原子（10 条）配两个参考级
   triton 内核（朴素 vs 手法），随测试集版本化存放（探针不进用例、不进
   评分，仅作实证工具）。同载体的探针可复用内核（如收缩类的朴素 GEMM
   探针被分块/split-K/偏置广播三条原子共用），实证结论仍逐原子独立出具；
2. **实证在真机验证窗口执行**（生成机无 NPU，满足 §1 约束）：每个手法
   原子在其覆盖用例上抽验，要求手法探针比朴素探针快 ≥ 1.5 倍的用例
   占比 ≥ 80%；
3. **不达标即降级**：任一手法原子未通过阈值 → 该原子标签保留（结构
   谓词仍成立）但披露口径改为"声明性考察（未通过收益实证）"，或将
   形状阈值上调后重新实证；覆盖率披露中"收益已实证"与"声明性"分开
   计数——杜绝装饰性标签；
4. **证据归档**：实证结果写入真机验证记录与健壮性发现文档，含逐原子
   的实测差距倍数。

### 3.4 判定与容差的特殊处理

- **并发累加（正确性负载）**：重复索引下浮点加法不满足结合律——参考
  实现必须以确定顺序累加（排序后累加），保证门禁"两遍一致"通过；
  实现与参考的顺序差异产生 ULP 级误差，由容差吸收。首批重复索引用例
  **限定整数数据类型**（精确、顺序无关）；浮点重复索引用例待真机归因
