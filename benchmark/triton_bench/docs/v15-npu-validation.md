## 尚未解决的部分

实际编译命令包含 `--mlir-print-ir-after-all`、`--mlir-print-ir-module-scope`、`--bishengir-print-ir-after=canonicalize` 和独立的 `--mlir-print-ir-tree-dir=...`。但捕获结果为：

- 实际后端编译的 stderr 只有编译警告，无 Before/After 快照。
- 没有采集到任何后端 saved MLIR 文件。
- JIT 原生 stderr 中，Neg 有 592 个 Before 段、Matmul 有 546 个 Before 段；二者 After 段均为 0。
- 这些捕获文本中没有 `hivm.hir.load` 或 `hivm.hir.mmad`，已绑定后端快照数量也均为 0。

因此，当前不是已有后端快照被离线数据流识别器误拒，而是缺少送入识别器的后端阶段产物。帮助中列出开关、进程接受开关并返回 0，并不证明此次编译实际输出了所需快照。

尚不能仅凭本次日志确定：为何已接受的开关没有产生所需后端产物，或者该构建应通过何种额外方式启用后端 dump。不能据此断言编译器没有实现两个模式，也不能改成普通 TTIR load/dot 即认证，或通过添加未经实证的 pass 名声称修复。后续应首先针对同一真实工具构建定位 dump 的启用和输出链路，再用逐字节绑定的真实产物验证；若修改冻结框架，应发布新版本，而非原地改写 v0.15。

后续已提供独立的双配置编译重放诊断，见 `docs/backend-dump-diagnosis.md`。它只复用本轮 Neg、Matmul 的两份真实编译输入，不执行 NPU 内核，也不改本报告或新增认证覆盖。诊断批次 `20261026-155402-979553` 已取得真实后端 IR，具体复核见 `docs/backend-dump-diagnosis-results.md`；正式快照和数据流识别仍需适配，不能据此将 v15 的两个标签改为已认证。
