## 仍需修改的正式认证链路

### 1. 函数级快照

本次后端输出是完整 `func.func`，不带外层 module。现有 `compiler_passes` 要求 `complete_module`，独立重读时两个算子的已接纳快照数仍均为 0。

后续应在保留输入、二进制和工具身份绑定的前提下，支持真实的完整目标函数快照：校验精确函数名、唯一性、完整函数体、合法截尾及实际 pass/phase，排除 HOST 辅助函数、其他内核、截断内容和跨段拼接。不能直接补造 `module { ... }` 当成原始模块证据。

### 2. Neg 的物理缓冲区和补零分支

真实目标链路为 GM 输入视图，经 `hivm.hir.load` 到 UB，再经 `vmul`、`vadd`，最终 `hivm.hir.store` 回 GM 输出。

现有 `MemoryFlow` 直接拒绝 `scf.if`，且只从 `memref.alloc/alloca` 识别片上缓冲区；真机使用 `hivm.hir.pointer_cast`，并有边界补零分支，因此当前仍不能认证。

这里不能简单地去掉条件控制流拒绝，也不能把每个 pointer_cast 的 SSA 名都当成独立内存。实际 Neg 的多个 UB 指针复用了相同物理地址。后续需要保守处理物理缓冲区别名、覆写、子视图与补零分支，保证真正载入的数据仍在最终输出依赖链中；条件执行的目标 load、死 load、结果被覆盖和不明控制流仍应拒绝。

### 3. Matmul 的真实后端形式

真机操作链是两路 GM 输入经 `hivm.hir.nd2nz` 写入 `#hivm.address_space<cbuf>` 缓冲区，再由 `hivm.hir.mmadL1` 写入 `#hivm.address_space<cc>` 累加缓冲区，最终 `hivm.hir.fixpipe` 写回 GM 输出。

现有识别器只处理另一种显式形式：`load -> l1 -> l0a/l0b -> hivm.hir.mmad -> store`，没有覆盖本次实际出现的 `nd2nz/mmadL1/fixpipe`、`cbuf/cc` 和物理指针形式；还会因补零 `scf.if` 拒绝整个函数。

后续应基于真实操作语义和完整数据流增加明确的后端形式支持，而不是仅增加几个操作名别名。必须证明两路输入各自供给矩阵运算、片上缓冲区与累加结果身份一致、结果流向真实 Out；处理有界非空 K 循环和条件补零，未知循环/分支、单边输入、死矩阵运算、未回写或被覆盖的结果仍不得认证。
