# Tensor 输出类型策略

2026-11-08 起，按项目负责人要求，输出类型使用 `isinstance(output, torch.Tensor)`，
不再要求实际类型精确等于 `torch.Tensor`。此调整落实 CodeCheck 的 G.TYP.08，
同时明确改变此前由项目自定的精确类型安全策略，不宣称两种策略安全等价。

## 接纳范围

- 普通 Tensor、Tensor 子类和 `torch.nn.Parameter` 不再仅因类型身份触发 `SUB-EXE-001`。
- 列表、元组输出仍逐项检查；不满足实例检查的包装器、普通对象仍触发 `SUB-EXE-001`。
- `isinstance` 本身可能认可伪装的 `__class__`，因此类型门禁不再承诺识别全部代理伪装。
- Tensor 子类可能通过 `__torch_function__` 执行自定义分派。这是放宽策略后的已知边界，
  不再承诺“判定前绝不执行子类分派”。后续检查抛错应记录为执行失败，不能直接授予通过。

## 保留检查

接纳类型不等于评测通过。设备、布局、输出数量、dtype、精度、输入不可变、计时完整性、
静态禁止委托和提交隔离继续执行。类型策略调整不取消这些判据，也不修改评分权重。

`ADV-D9-tensor-subclass` 仍保留原返回子类的计算行为，但不再承担“子类必须拒收”的正控制。
原对抗集文档的历史实测结论保留历史含义，不是当前策略下的新认证结果。

## 验证口径

本地回归覆盖普通 Tensor、子类、孙类、Parameter、伪装、代理、嵌套输出以及后续设备和布局检查。
真机端到端结果需使用本次代码重新运行，不能沿用旧策略的 NPU 结果声明通过。

## 测试协议夹具调整

2026-11-09 为落实 G.NAM.05，运行期测试不再自行定义 `__torch_function__` 和 `__class__`。
真实 Tensor 子类、孙类及 Parameter 的接纳测试保留；标准库 `Mock(spec_set=torch.Tensor)`
提供实例身份伪装，用普通 `is_contiguous` 方法的故障验证类型门禁之后仍实际执行布局检查。
PyTorch 自带 `TorchFunctionMode` 的默认分派会抛出 `NotImplementedError`，用于验证分派异常
向外传播，退出上下文后同一输出恢复正常检查，覆盖单输出、嵌套输出及真实子类。

这是按当前策略拆分测试职责，不是把原协议方法改名、动态安装、生成源码或排除扫描。
模式分派不等同于提交方自定义的子类分派，测试不再单独构造“子类覆盖分派并伪装类属性”的组合，
也不证明所有恶意子类都会失败。类型身份伪装、真实子类接纳、后续检查调用和分派故障分别验证；
此前披露的代理伪装和子类分派安全边界不因此收紧。
