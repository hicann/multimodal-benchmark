这是新的冻结候选版本，不修改或重新冻结 v0.13。全部 1,377 个用例编号、内容哈希、输入、参考函数、容差与 71 个标签分母保持不变，原有 1,360 个基础用例全部保留。提交侧所有 Python 内核与 v0.13 逐字节一致，本次不在尚无反证时修改已通过正确性验证的内核。

## 新增采集

仅在正确性 JIT 调用范围内截获 `subprocess.run` 发起的 `bishengir-compile`，结束或异常均恢复原方法，不在性能采样范围安装钩子。

- 使用实际安装的编译器 `--help`，仅在其广告支持时使用 `--help-hidden`，只追加帮助中明确列出的 IR 输出与 module-scope 选项。不猜测后端是否支持某个开关，不启用内核断言，不改变输入或算法优化选项。
- 保存实际编译命令、工具可执行文件 SHA256、帮助产物、原始 MLIR 输入、编译输出文件 SHA256，以及原调用返回的 stdout/stderr。解决编译器把输出放入子进程 PIPE 后，父进程文件描述符重定向无法得到该部分日志的问题。
- 在输入所在目录采集本次调用新建或改变的有界 MLIR 文件；不扫描全盘，不主动修改编译器源文件，不伪造保存文件对应的 pass 阶段。
- 编译失败时保留已经取得的后端产物并传播原异常，不伪造成功的 JIT launch。
- 产物继续压缩、按内容去重，并进入 supervisor 的哈希索引。过大截断的日志不参与认证；不支持的后端调用方式、没有输出或未知格式均保持未认证。

## 输入—二进制绑定与识别

后端日志在进入特性认证之前必须同时满足：输入文件内容等于该 JIT 返回的 `ttadapter`，输入 SHA256 正确，编译成功，输出文件 SHA256 等于该 JIT 返回的 `npubin`。原始后端日志本身不直接进入认证器，避免绕过绑定。

每个完整快照仅分析同名内核，Before/After 分开保留，不拼接跨 pass SSA；保存文件只标注为 saved snapshot，不伪称 After-pass。Before 快照可以证明其中明确存在的实际结构，但普通 `memref.copy`、默认地址空间申请和 `linalg.matmul` 仍不能据此补分。

仅允许在同一进程、同一运行目录、同一 manifest 内复用输入和二进制哈希完全相同的后端证据。JIT 从缓存返回并不意味着重新编译，报告单独标记复用。

显式昇腾内存数据流认证继续要求真实输入、明确 UB 或 L1/L0A/L0B 存储层级、活跃计算依赖和最终输出。补充支持显式地址空间的 `memref.alloca` 与带 SSA 结果的 DPS 操作；拒绝不能证明路径关系的条件控制流。性能收益及昇腾片上存储与共同确认特性清单的对应关系仍不自行宣称已验收。

## 真机范围与结果解释

入口：`bash scripts/coverage-backend-verify.sh`。只跑 Neg 20 例与 Matmul 20 例，不跑其他算子，也不接受扩大范围的参数。

结果中的 `backend_evidence` 分别记录外部编译调用、缓存复用、输入/二进制绑定、可用快照数量和采集说明。终端另行打印 `FA-PAT-VEC-LOAD`、`FA-PAT-TILE-GEMM` 的 compilation/execution_validation 状态。

40 例 PASS 只表示功能验证通过，不能替代这两个模式的认证。模式缺证时必须保留 False。只有真实产物满足要求且对应运行 PASS 后，才允许将该标签加入叠加分析；若两项均补齐，预期上限为 67/71，而不是当前已经达到。

本次修改涉及冻结框架，必须提交、发布 v0.14 后再在真机运行；不以 v0.13 名义运行新版认证器，也不复用旧全量报告的冻结验收标志。结果分支仍为现有 GitCode 仓库的 `npu-results`。
