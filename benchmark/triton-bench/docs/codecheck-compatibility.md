# CodeCheck 整改后的兼容性修复

## 修复范围

本修复以 `feat/add-triton-bench` 分支、`5c164d1` 之后尚未提交的质量整改为输入。保留已有 license 头、格式和命名整改以及 YAML 生成日志，不回退至整改前源码。

- 对外入口与内部实现分离。ArgMax、SwiGlu、Cummin、CrossEntropyLoss 保留内部改名，通过明确的兼容入口满足既有参数契约；必要的内建名称仅在公开入口行精准标注，不放宽加载规则。
- 命令行输出通过 logging handler 写入明确的 stdout/stderr，保留分隔符、换行和立即输出行为。库调用不依赖 `__main__` 初始化日志，不修改宿主根日志器；输出失败继续作为错误传播。
- 构建模板与现有修正后的示例保持一致，区分维度、指针与索引变量，避免命名整改改变寻址、掩码和分块计算。
- YAML 日志使用原子替换和写入锁，多个写入实例不会相互覆盖；保留历史 JSONL 的只读解析能力，损坏日志不能被静默视为空记录。
- 认证器对经过审核的新旧内核源码分别做完整 AST 指纹匹配，再按形参位置建立语义角色。原始源码、IR、张量绑定和历史记录不被重写；未知源码、错误绑定与缺失证据继续拒绝认证。
- 仅随仓补齐两个被直接依赖的参考来源 JSON 元数据，不重新引入大体积参考实现目录。

## 冻结资产修订

用例 `manifest.json`、规范、容差和评分配置未修改。原冻结资产索引逐字保存在各语料的 `evaluation-assets-history/` 中，新索引通过 `evaluation-assets-migration.json` 明确标识 `codecheck-compat-20261102` 修订。
