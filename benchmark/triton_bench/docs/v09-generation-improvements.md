# v0.9 用例生成机制改进与验收边界

本轮依据根目录《评测任务.md》改进官方来源候选集的生成机制。原有 68 个算子的来源锁、独立参考实现和判定容差保持有效；新版本生成时发布为候选集，须以新的 NPU 证据申请资格。本文不代表完整任务验收，也不代表双方已确认核心特性清单。

2026-10-24 后续真机验证：提交 `54c9bb3` 的 1360 例全部完成，1358 PASS，
FloorDiv 两个边界用例 WRONG_RESULT；已获得 50 算子/1000 例冻结资格，
冻结集静态标签覆盖率为 49/71 = 69.01%。这仍未达到 90% 要求。
原始结果复核、失败范围和后续提交修复见 [v0.9 真机分析](v09-npu-results-analysis.md)。
下文生成阶段的 CPU 校验记录与当时的候选状态保留，以区分不同阶段的证据。

| 任务书要求 | 本轮实现与验证 |

## 具体行为变化

原生成器只有连续二维输入，数值模式隐藏于 `seed % 4`，且所有用例均记为 normal。新版本显式生成 normal、boundary、zeros、mixed、extreme。zeros 作用于主数据输入；Where 的布尔条件不再被误当作主数据处理。mixed 保证同时包含零和非零。extreme 仅在明确允许的 float32 算子上将主输入放大 20 倍；未开放的组合会报告原因，不会静默改写成其他分布。Log、Log2、Log10、Rsqrt、Pow 不生成全零或混零输入。

布局构造曾把 `[原始数据, 零]` 隔位取样，改变了逻辑数值。现在先创建间隔存储，再把原始数据逐元素写入偶数位置，保证逻辑数据和负零符号不变。官方逐元素内核同步使用主输入步长读取；辅助输入仍连续，不通过主机复制规避跨步输入。非逐元素算子及任意转置步长不在本轮开放范围内。

较大负载按算子族设计：逐元素采用宽向量；逐行算子使用更多行并限制末轴宽度；Matmul 单独限制 M，避免既有权重 `(K, M+3)` 规则造成输出意外平方增长。四档规模按主输入元素数统计，不能等同于 FLOP 或实测性能。

新选择器从已选边界锚点计算边际收益，严格遵守每算子 20 例，依次考虑新增标签、dtype/规模/rank/布局/分布维度、属性差异和成本。去重使用完整的 value_range，忽略单纯 seed 差异。固定预算下无法保留的标签和维度会显式列出；该贪心算法不声称对任意候选池都达到最优。

新集在本次实际选择中没有丢失任何候选池可触达标签或上述单维分层。50 算子选择对 v0.9 使用“类别/算子族多样性，再优先新增标签”，避免旧轮转策略丢掉 Gelu 唯一标签；仍须先满足同环境、整算子 20/20 PASS、CPU/NPU 双参考门禁和完整性要求。旧版本选择策略保持原样，不能借用旧运行结果给新输入授予资格。

## 实际覆盖与规模

覆盖率是**全体用例 feature_atoms 的并集 / 全部 active 标签**，不是各算子或类别覆盖率的平均值。`coverage.json` 同时给出逐算子统计，逐算子数值不参与全局平均。

| 数据集 | 算子/用例 | 静态标签覆盖 |
| --- | --- | --- |
| 上轮真实 NPU 冻结集 | 50 / 1000 | 33/71 = 46.48% |
| 上轮完整官方候选集 v0.8 / v0.8.1 | 68 / 1360 | 34/71 = 47.89% |
| 本轮 v0.9 候选集 | 68 / 1360 | 49/71 = 69.01% |

比较同为 68 算子的候选集，本轮新增 15 项标签，提高约 21.13 个百分点。新集有 159 例跨步输入；一维、三维、四维各 48 例；SMALL/MEDIUM/LARGE/XLARGE 分别为 1106/119/68/67 例；normal/boundary/mixed/zeros/extreme 分别为 966/145/141/86/22 例。

现有标签器将输入 rank 映射为 `FA-PROG-GRID*`，这些是既有的静态代理标签，**没有验证实际内核采用对应维数的 launch grid**。pattern 标签同样表示负载结构，不证明被测编译器使用了相应优化。69.01% 不等于执行期 Triton API、IR、指令覆盖率，也不等于通过率。

当前池仍有 22 项 active 标签不可触达。达到 90% 至少需 64 项，本轮还差 15 项。缺口包括 BF16/其他整数 dtype、首轴/中轴、Scatter/并发累加、多输出、融合组合、静态展开和部分归约/扫描/收缩优化负载。进一步补齐必须扩展对应算子语义、输入契约、独立参考和实际内核；不能通过缩小分母、手工补标签、重复 seed 或降低精度标准完成。

若假设所有候选均重新通过 NPU 门禁，新的 50 算子选择在静态演练中可保留 49 项标签。该演练只验证选择机制，**不是新的 50 算子资格结论**。

## 验证与运行

本轮本地验证环境为 macOS、Python 3.9.6、Torch 2.2.2、NumPy 1.26.4；项目声明的正式环境要求 Python ≥3.11，因此这里仅记录开发机 CPU 校验结果，不能代替正式环境资格检查。新集构建已对全部 1360 例执行 CPU 上 Torch 与独立 NumPy/scalar 参考门禁，失败数为零。新增回归检查实际输入值、合法域、条件/索引约束、确定性、跨步数据与符号保持、固定预算以及稀有标签保留。完整回归为 681 passed、163 skipped；跳过项依赖 NPU 或本机缺失的运行环境。新冻结资产指纹检查通过，重新生成的 1360 例与冻结清单逐项一致。

```bash
python scripts/build_official_corpus.py
bash scripts/official-suite-verify.sh
```

第一条命令对已存在的新冻结集校验指纹，拒绝隐式覆盖。第二条默认指向 v0.9，需要真实昇腾环境。其默认 smoke 配置用于功能验证；正式性能结论仍需按运行规范使用标准重复测量配置。本机没有 NPU，因此本轮没有产生新的 NPU 通过率或性能结果。

v0.8 和 v0.8.1 文件保留原样。因生成器、输入构造和框架资产已升级，在当前代码上校验旧集会正确报告资产指纹不同；重放旧证据应使用其原始代码及依赖快照，不应更新旧冻结指纹来绕过保护。
